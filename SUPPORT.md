# Support

## Getting help

Use GitHub issues or discussions for project support when available.

Before opening an issue:

- search existing issues,
- read the relevant docs,
- prepare a minimal example,
- remove secrets and customer data.

## Good support request

A good support request includes:

- Recon version,
- operating system,
- Python version,
- command run,
- contract snippet,
- error output,
- expected behavior,
- actual behavior,
- minimal reproduction.

## Do not share secrets

Do not share:

- credentials,
- private keys,
- tokens,
- customer data,
- production evidence containing sensitive values.

Use fake examples or redacted snippets.

## Types of issues

Use issues for:

- bugs,
- documentation problems,
- feature requests,
- unclear validation errors,
- adapter behavior problems,
- reproducible examples.

Use discussions for:

- design ideas,
- questions,
- use-case exploration,
- community package ideas.

## Commercial support

No commercial support commitment is defined in this repository.
